让 Agent 扛得住真实世界

第 3 课的 Agent 能跑了。这一课处理它跑不稳的三个原因。

约 25 分钟 产出：exercises/04_resilient_loop.py 会真的花钱，几分

先看看它有多脆弱

把第 3 课那份代码里的 add(a, b) 换成 divide(a, b)，让模型算「10 除以 0」。会发生什么？a / b 抛出 ZeroDivisionError，异常从工具函数一路冒出循环，整个程序崩掉。用户看到的是一屏 Python 报错，不是一个「抱歉，这个算不了」的回答。

这不是边缘情况。你交付给客户的 Agent，工具迟早会遇到：参数超出范围、下游服务超时、权限不足、数据库锁住。一次工具失败就把整个程序拖垮，是不能上线的。

今天处理这四个问题里的前两个（其余两个留给下一课，见课末）：

问题今天的答案
工具执行时抛异常接住它，报回给模型，不让它冒出循环
模型编造了不存在的工具名顺带解决：查表失败本身就是一种异常
历史超出上下文窗口下一课
危险操作要不要先问人今天也处理：执行前先确认

第一件事：把异常变成模型能读的话

循环骨架不变，只改「执行工具」这一步。核心手法在 协议速查 已经放了：

try:
    output = TOOLS[call.name](**call.input)
    is_error = False
except Exception as e:
    output = f"工具执行失败：{e}"
    is_error = True

然后把 is_error 也塞进 tool_result：

{
    "type": "tool_result",
    "tool_use_id": call.id,
    "content": str(output),
    "is_error": is_error,   # ← 新增
}
为什么不是"捕获异常然后返回一个默认值"

如果你只是 except: output = None，模型会把 None 当成一个正常答案去用，编出一个听起来合理但错误的回复。把真实的错误信息原样报回去，模型才有机会自己判断："除数是 0，这题没法算" 或者 "让我换个参数再试一次"。is_error: True 是给模型的明确信号，比让它自己从文字里猜更可靠。

免费获得的第二件事：幻觉工具名

模型偶尔会编出一个 TOOLS 里根本不存在的工具名（尤其模型换成更弱的那一档时更常见）。查表的那一行 TOOLS[call.name] 会抛 KeyError，而这正好落进你刚写的 try/except 里，和其它异常一样被接住、变成一句错误信息报回去。

你不需要专门写一层「检查工具名是否存在」的代码。把执行整体包进 try/except，顺带就把这个问题解决了。这是今天最省力的一个收获。

第三件事：危险操作，执行前先问人

练习里新增了一个 delete_note（模拟删除笔记）。这类操作一旦执行就不可逆，不能完全交给模型自己判断"要不要做"，它的判断依据只是概率，不是责任。

做法很朴素：维护一份"危险工具"名单，执行前用 input() 问一句，人不确认就不执行：

DANGEROUS = {"delete_note"}

if call.name in DANGEROUS:
    reply = input(f"要执行 {call.name}({call.input}) 吗？(y/n) ")
    confirmed = reply.strip().lower() == "y"
else:
    confirmed = True

拒绝时怎么办？别静默跳过，还是要报一个 tool_result 回去，只是内容变成"用户拒绝执行此操作"，is_error 设成 True。这样模型知道发生了什么，能对用户说清楚，而不是卡住或者装作没这回事。

这一步在真实项目里会怎么变

input() 只是终端里的教学替代品。接给客户的产品里，"问人"通常是：把这次请求暂停，推一条确认消息到前端，等用户点"确认"按钮，你的后端再继续执行。机制是一样的：执行前有一个明确的人工确认关口，只是把 input() 换成了一次真正的交互。

参考答案（自己写完再打开） 
confirmed = True
if call.name in DANGEROUS:
    reply = input(f"  [需要确认] 要执行 {call.name}({call.input}) 吗？(y/n) ")
    confirmed = reply.strip().lower() == "y"

if not confirmed:
    output = "用户拒绝执行此操作"
    is_error = True
else:
    try:
        output = TOOLS[call.name](**call.input)
        is_error = False
    except Exception as e:
        output = f"工具执行失败：{e}"
        is_error = True

results.append(
    {
        "type": "tool_result",
        "tool_use_id": call.id,
        "content": str(output),
        "is_error": is_error,
    }
)
