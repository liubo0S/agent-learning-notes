第 1 课

Agent 的心脏是一个 while 循环

你已经会 for 和 if。今天加三个新语法，把 Claude Code 的内核亲手写出来。

约 25 分钟 产出：exercises/01_agent_loop.py 不联网、不装依赖、不需要 API key

为什么从这里开始

你每天在用 Claude Code。它读文件、跑命令、改代码，看起来像个黑盒。

剥掉工程外壳之后，里面是一个循环加一张函数表。就这样。今天你会把这个内核写出来，从此整个领域对你都有了坐标原点：之后学的每一个框架、每一篇论文、每一次报价，都是在往这个循环上加东西。

而这直接指向你的目标。你要独立接活交付，而不是拼一个 demo。框架会把这个循环藏起来，可是客户的怪需求全都落在循环里：这一步要不要人工确认、工具报错了怎么退、跑到第几轮该停下来收手。能自己掌控循环的人，才有报价的底气。

一个 LLM 其实什么都做不了

先接受这件事：模型唯一的能力是把文字变成文字。它不能查天气、不能读你的文件、不能发邮件。

所谓「工具调用」，实际发生的是这样一件事：

  1. 你在提示里告诉模型：你可以用 get_weather，参数是城市名。
  2. 模型输出一段结构化文字，意思是「我想调用 get_weather，参数填杭州」。它并没有真的去查。
  3. 你的代码看懂这段文字，真的去执行那个函数，拿到结果。
  4. 你把结果作为新的输入塞回对话，再问模型一次：现在你想干什么？
  5. 重复，直到模型不再要求调工具，而是直接给出答案。

第 5 步那个「重复」，就是 Agent 和普通一次性调用的全部区别。Anthropic 在 Building Effective Agents 里把这条线画得很清楚（以下是转述，非原文引用）：如果执行路径是你事先用代码写死的，那叫 workflow；只有当模型自己决定下一步用什么工具、什么时候收手，才配叫 agent。

今天要装进脑子的一句话

Agent ＝ 循环 ＋ 一张工具表 ＋ 一个退出条件。
工具是普通函数，循环是 while True，退出条件是模型说「我说完了」。

  1. 打开 exercises/01_agent_loop.py。先从上到下读一遍，看懂三层结构：工具、假模型、循环。
  2. 补 TODO 1：把两个函数注册进 TOOLS。
  3. 补 TODO 2：模型说完了就打印并 break。
  4. 补 TODO 3：否则查表、调用、打印、把结果 append 进 history。
  5. 删掉那行 raise SystemExit(...)，然后运行：
    python3 exercises/01_agent_loop.py

写对了，你会看到正好这三行（我已经跑过一遍验证过）：

[工具] get_weather -> 杭州今天晴，26 度
[工具] add -> 30
[回答] 杭州今天晴，26 度；再加 4 度是 30 度。

看到这三行的时候请停一秒：这就是一次完整的 Agent 运行。模型连着调了两个工具，拿到结果，然后自己决定收手。你手上的 Claude Code 做的事，在结构上和它一模一样。

卡住了？先看提示，别急着看答案

报 KeyError：TOOLS 的键要和 FAKE_RESPONSES 里的 name 完全一致，是 "get_weather" 不是 "getWeather"。

报「模型被调用的次数超过预设」：循环没能 break。检查 TODO 2 的判断是不是写成了 =（赋值）而不是 ==（比较）。

程序卡住不动：history.append(result) 漏了。假模型靠 history 的长度决定下一步，历史不增长它就永远返回同一个动作。

报 TypeError: add() takes 2 positional arguments：fn(step["args"]) 少了 **，把整个 dict 当成一个参数传进去了。

参考答案（先自己写完再打开，这个顺序很重要） 
TOOLS = {"get_weather": get_weather, "add": add}


def run_agent():
    history = []

    while True:
        step = fake_model(history)

        if step["type"] == "text":
            print("[回答]", step["text"])
            break

        fn = TOOLS[step["name"]]
        result = fn(**step["args"])
        print("[工具]", step["name"], "->", result)
        history.append(result)

十一行。这就是 Agent 的心脏。剩下的一切都是在往它身上加：真模型、错误处理、并发、权限、成本控制。

顺手记一个前端迁移者的坑

你可能想写 if history: 来判断历史是否为空。在 Python 里这是地道写法，但要注意行为和 JS 不同：空列表 [] 和空字典 {} 在 Python 里是假值，而 JS 里 if ([]) 是成立的。这个差异会在 Agent 代码里反复咬人，因为消息历史、工具参数几乎都是列表和字典。速查表的「七个坑」里有全部七条。
