工具调用协议速查

一次工具调用在 messages 里到底长什么样。字段名全部取自 SDK 类型定义。

设计为可打印字段已用 inspect 核对SDK 0.121.0

一句话概括

模型请求调用工具（tool_use），你的代码执行，你把结果报回（tool_result）。
三个动作，两条消息，靠一个 id 串起来。

完整往返：四步

步谁messages 里新增的内容
1你 {"role": "user", "content": "杭州天气怎么样？"}
请求里同时带上 tools=[...]
2模型 stop_reason == "tool_use"，content 里出现 tool_use 块。
把整个 resp.content 原样追加为 assistant 消息。
3你 执行函数，把结果包成 tool_result 块，
追加为 role: "user" 的消息（不是 assistant）
4模型 带着完整历史再问一次。它可能给最终答案（end_turn），
也可能要求再调一个工具（回到第 2 步）

三种结构的字段

工具声明（放进 tools=[...]）

{
    "name": "get_weather",                  # 必填。要和你的查表键一致
    "description": "查询某城市天气。当用户问到天气时使用。",
    "input_schema": {                        # 必填。标准 JSON Schema
        "type": "object",
        "properties": {
            "city": {"type": "string", "description": "城市名"},
        },
        "required": ["city"],
    },
}

技术上只有 name 和 input_schema 必填，但省掉 description 等于让模型盲选。 JSON Schema 常用类型名：string、number、integer、boolean、array、object。

tool_use 块（模型给你的，是对象，用点号取值）

字段说明
.id本次调用的唯一标识。报结果时必须原样带回
.name工具名，用它查你的函数表
.input参数，是一个 dict。用 fn(**block.input) 展开调用
.type固定为 "tool_use"

tool_result 块（你给模型的，是字典）

{
    "type": "tool_result",        # 必填
    "tool_use_id": block.id,      # 必填。和上面的 .id 配对
    "content": str(result),       # 字符串。数字要 str() 一下
    "is_error": False,             # 可选。工具报错时设 True
}
方向不对称，别记混

模型给你的块是 SDK 对象，取值用点号：block.input。
你给模型的块是 普通 dict，构造用键：{"tool_use_id": ...}。
还有个不对称：字段名一个叫 id，一个叫 tool_use_id。

stop_reason 的取值

循环的判断依据。以下是 SDK 类型定义里的完整列表：

值含义与该做什么
"tool_use"要求调工具。执行后继续循环
"end_turn"说完了。退出循环，这是正常终点
"max_tokens"被 max_tokens 截断了。回答不完整，要么调大，要么当失败处理
"stop_sequence"撞上了你设的 stop_sequences
"refusal"模型拒绝回答
"pause_turn"长任务中途暂停，需要你把它原样续上
"model_context_window_exceeded"历史超出上下文窗口。必须裁剪或摘要

写循环时不要判断 == "end_turn" 才退出。用 != "tool_use" 退出，这样上面那些异常情况都会落进退出分支，而不是让循环空转。

一轮可能有多个工具调用

模型可以在同一轮里要求调好几个工具（并行）。所以：

  • tool_use 块要用列表推导式全部筛出来，不能只取第一个
  • 所有 tool_result 块放进同一条 user 消息的 content 列表里
  • 少报一个，服务端就会报错
calls = [b for b in resp.content if b.type == "tool_use"]

results = [
    {"type": "tool_result", "tool_use_id": c.id, "content": str(TOOLS[c.name](**c.input))}
    for c in calls
]

messages.append({"role": "assistant", "content": resp.content})
messages.append({"role": "user", "content": results})

报错对照表

现象原因
400，说 tool_result 找不到对应的 tool_use忘了把 assistant 那一轮追加回 messages
400，说少了 tool_result模型一轮要了多个工具，你只报了一个
KeyError声明里的 name 和函数表的键不一致
TypeError，参数不匹配input_schema 的属性名和 Python 函数的参数名不一致
模型该用工具却不用description 太含糊。这是提示词问题，不是代码问题
模型选错了工具两个工具的 description 界限不清
AttributeError，某块没有 .text取值前没按 type 筛。思考块没有 .text

工具报错怎么办

不要让异常冒出循环。把错误当成结果报回去，模型往往能自己改正（比如换个参数重试）：

try:
    output = TOOLS[call.name](**call.input)
    is_error = False
except Exception as e:
    output = f"工具执行失败：{e}"
    is_error = True

results.append({
    "type": "tool_result",
    "tool_use_id": call.id,
    "content": str(output),
    "is_error": is_error,
})

这是 Agent 可靠性的核心手法之一：把失败变成模型能读懂的输入，而不是让程序崩掉。
